# SwingSet Project Overview

## Working product name
SwingSet

## Product summary
SwingSet is a private, invitation-only social interaction app for hosted events. It is designed to help attendees connect in person through guided participation, icebreakers, event-specific games, and privacy-respecting contact exchange.

The product may support lifestyle/swinger communities, but it must also be adaptable to vanilla or non-lifestyle audiences. The app is not intended to promote sex, hookups, explicit content, or in-app chatting. Its purpose is to create fun, structured, real-world social interaction.

## Core goals
- Encourage people to put phones down and talk
- Help hosts run better social events
- Help attendees connect through guided participation
- Support consent-aware, privacy-respecting interaction
- Make event experiences feel premium, exclusive, and intentional

## Product positioning
SwingSet should feel:
- premium
- exclusive
- event-based
- private
- intentional
- socially engaging

SwingSet should not feel like:
- a dating app
- a hookup app
- a chat app
- an explicit app
- a generic party game app

## Audience
Primary audience:
- event hosts / promoters
- attendees

Audience support model:
- built for lifestyle/swinger communities
- adaptable to vanilla/non-lifestyle social events
- configurable by event type and host needs

## Access model
- invitation only
- no attendee search/discovery
- private profiles
- event-specific participation

## Core product rules already established
- App name: SwingSet
- Default attendee language: attendees
- Attendee profiles are detailed before the event
- Profiles can be edited before the event
- Some profile edits may be limited during an active event
- Event-day photo is required when the event begins, not at install
- Profiles become dormant after the event
- Contact exchange is mutual only
- No in-app messaging
- Hosts can manage events live and adapt during the event
- Events may be single-venue or multi-venue

## Current roadmap structure
- Phase 0 — Product Rules and Scope
- Phase 1 — Foundation, Onboarding, Check-in, and Event Activation
- Phase 2 — Host Event Creation and Management
- Phase 3 — Game System Design
- Phase 4 — Real-World Interaction Layer
- Phase 5 — Venue and Route System
- Phase 6 — Contact Exchange and Privacy
- Phase 7 — Persistence and Production Hardening

## Current project status
- Core product direction defined in roadmap docs
- Phases 0, 1, and 2 are marked Ready for Execution
- Phases 3–7 contain goals and open decisions that still need discovery and definition

## Recommended working method
- Discovery first
- Ask focused questions in small batches
- Document decisions before coding whenever possible
- Mark stages as Ready for Execution before implementation
- Keep tracking docs updated continuously

## Key principles for future development
- Real-world interaction comes first
- The phone should support connection, not replace it
- Privacy and consent are part of the product, not bolt-ons
- Hosts need flexible live control
- The app must be usable by non-technical operators and guests
