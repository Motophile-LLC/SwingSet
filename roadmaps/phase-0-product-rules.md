# Phase 0 — Product Rules and Scope

## Goal
Lock the product identity, tone, audience, boundaries, and event-level scope.

## Locked decisions
- App name: **SwingSet**
- Default attendee language: **attendees**
- Tone: **premium and exclusive**
- Audience: **hosts and attendees equally**
- App should never feel like:
  - dating app
  - hookup app
  - chat app
  - explicit app
  - generic game app
- Primary goal: encourage people to **put phones down and talk**
- Access: **invitation only**
- Guest discovery: **no search**
- Profile privacy: **private**
- Event type: **any event type**
- Event flow: **event-specific**
- Game set: **event-specific**
- Event duration: **flexible** (flexible timing; host can improvise)
- Host structure: **multiple hosts**
- Host control: **live editing** (edit in real time if something unexpected happens)
- Events can be:
  - single venue
  - multi-venue / multi-destination
- Host creation:
  - wizard with presets and custom options
  - defaults from templates
  - can duplicate past events
- Host feedback:
  - hosts can rate games for success/what worked vs didn’t
  - the app learns what works for that host
- Profiles:
  - detailed onboarding before event
  - editable before event
  - profiles become **dormant after the event**
- Contact sharing:
  - mutual only
  - set by attendee (what is public vs shared by tap)
  - no in-app messaging
- Recognition:
  - event-day photo required **when the event begins** (not at install)

## Privacy controls (attendee-owned)
- Attendees decide what is public vs private.
- Some fields become visible only after verified/tap confirmation.

## Contact exchange
- After a verified, mutual meeting, attendees can share:
  - permitted contact info and/or
  - links to profiles
- The app should not enable in-app chat; contact exchange is intentional and consent-based.
